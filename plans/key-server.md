# Сервер-ключник для ИИ

Только план, не реализовано. Основной план — `../PLAN.md`, ИИ сейчас — `ai.md`.

## Суть

Приложение ходит не к провайдеру, а к нашему тонкому бэку по внутреннему ключу приложения. Бэк проверяет его
и проксирует запрос в DeepSeek своим ключом. Пользователь ничего не вписывает, «AI key» в Settings уходит.

## Сервер

- `server/` в этом репо: Python + FastAPI, запуск через uv, Dockerfile. Один эндпоинт `POST /v1/chat` — тело как у
  OpenAI chat completions (`messages`, `temperature`), модель сервер ставит сам (`deepseek-chat`).
- Секреты из env: `DEEPSEEK_API_KEY`, `APP_KEYS` (список внутренних ключей, чтобы можно было ротировать).
  В git — только `.env.example`.
- Проверка `Authorization: Bearer <app key>`, иначе 401. Лимиты: запросов в минуту на ключ и дневной потолок
  токенов/денег на весь сервер — выше него 429. Ограничение размера тела и `max_tokens`.
- Логи без текста запросов: время, код, токены. Таймаут к DeepSeek, ошибки провайдера → 502.
- Хостинг — дешёвый VPS или любой контейнерный хостинг с HTTPS; решить при реализации.

## Приложение

- URL сервера и ключ приложения — из `local.properties` в `BuildConfig` (не в git). Нет их — ИИ выключен, как сейчас
  без ключа.
- `data/ai/Ai.kt`: один путь — OpenAI-совместимый запрос к серверу; `Provider`, определение провайдера по ключу
  и Claude-формат убрать. 401 → «ИИ недоступен», 429 → «лимит на сегодня».
- Убрать экран `AiKeySettings` и пункт 8 из `screens.md`; `ai.md` переписать под сервер.

## Безопасность

Внутренний ключ лежит в APK и достаётся декомпиляцией — он защищает только от случайных запросов. Настоящая
защита — лимиты на сервере и потолок расходов в кабинете DeepSeek. Для релиза другим — вход пользователя и
подписка (`release.md`) вместо общего ключа.

## Цель

Личное Android-приложение: берёт главы учебника English File и учит по ним —
общий движок упражнений + контент отдельно, без переписывания кода под каждую
тему. Новая глава = новый файл данных, а не новый экран.

## Зафиксированные решения

| Вопрос | Решение | Почему |
| --- | --- | --- |
| Платформа | Android-only, Kotlin + Jetpack Compose | Веб не нужен |
| minSdk | 31 (Android 12) | Целевой телефон — Android 12 (HiOS). Никаких костылей совместимости |
| compileSdk / targetSdk | последний stable из SDK Manager | Требований Play нет, можно всегда свежий |
| Модулей | один `:app` | Личное приложение, многомодульность — оверинжиниринг |
| Контент главы | Kotlin-объекты в коде | Компилятор ловит опечатки в схеме, ноль парсинга и рантайм-ошибок |
| Прогресс | Room | Локально, без сети и аккаунтов |
| Распространение | подписанный release APK вручную | Можно поставить с телефона без компьютера, Play не нужен |
| Версии библиотек | не фиксируем в плане | Берём то, что сгенерит визард Studio, в `gradle/libs.versions.toml` |
| Роль приложения | дополнение к занятиям с учителем, не замена | Урок — у учителя, приложение — закрепление и повторение |
| Откуда упражнения | весь урок: SB, Grammar/Vocabulary Bank, WB | WB и GB задаёт учитель; говорение/письмо проверяет ИИ (опционально) |
| Открытие | автоматически по мере прогресса, глава за главой | Никаких ручных отметок — приложение само ведёт по книге |
| Темп | одна текущая глава, медленно и глубоко, до освоения | Так идут занятия с учителем — несколько уроков на главу |
| Учителю | ничего не показываем, приложение только для меня | Без экспорта и отчётов |
| Комментарии | ни одного: ни в Kotlin, ни в Python, ни в XML/конфигах; KDoc и docstring тоже нет | Код объясняет себя именами, типами и константами; «почему» — в `plans/` |
| Линтеры | строгие, всё — ошибки: detekt (`allRules`) + compose-rules, ktlint, Kotlin `allWarningsAsErrors`, Android Lint; для `tools/` — ruff (`ALL`) и mypy strict | Подавления (`@Suppress`, `noqa`, `type: ignore`) не используем — правим код |

**Проверки перед сдачей работы** (из корня; все должны быть зелёными):
- Kotlin: `./gradlew :app:ktlintFormat :app:ktlintCheck :app:detekt :app:testDebugUnitTest :app:lintDebug`.
  Отчёт detekt — `app/build/reports/detekt/detekt.sarif`, lint — `app/build/intermediates/lint_intermediate_text_report/debug/lintReportDebug/lint-results-debug.txt`.
- На телефон — только release: `./gradlew :app:installRelease` (R8 + baseline profile; тот же ключ, ставится поверх
  debug с сохранением данных). Debug на слабом телефоне заметно тормозит — для проверки скорости не годится.
  Свой baseline profile приложения не генерируем: нужен API 33+ или root, телефон — API 31 без root (только профили библиотек).
- Python: `uvx ruff format tools`, `uvx ruff check`, `uvx --with pymupdf --with numpy --with pillow mypy`,
  `PYTHONIOENCODING=utf-8 python tools/check_no_comments.py`.
- Хук `.claude/settings.json` → `tools/lint_hook.py`: после каждой правки `.py` — ruff и проверка комментариев.
- Конфиги: `config/detekt/detekt.yml`, `.editorconfig`, `pyproject.toml`, блок `lint {}` в `app/build.gradle.kts`.

## Риски

- **Ошибка транскрипции → учим неверному.** Главный риск проекта. Ручная сверка
  по скану + content-тесты (механика). Смысл тесты не проверяют — только глаза.
  Ответы из ключа WB надёжны; ответы `MODEL` (SB) — самое слабое место: в UI не
  выделены, поэтому их вычитываю в конвейере, а найденное учителем правлю в JSON.
- **Стабильность id.** Прогресс в Room привязан к `exerciseId`. Переименовал id —
  потерял прогресс по упражнению. Правило: id не меняется никогда, даже если
  правим текст упражнения.
- **Строгость нормализации.** Слишком строго — фрустрация на верных ответах,
  слишком мягко — пропускаем ошибки. Когда ловим ложное «неверно», добавляем
  вариант в `answers` конкретного упражнения, а не ослабляем нормализатор.
- **Потеря keystore.** Обновление «поверх» станет невозможным — только
  переустановка с потерей данных Room. Бэкап keystore обязателен (Э7).
- **HiOS.** Агрессивно чистит фон. Приложению фон в v1 не нужен, риск низкий.
  Если позже добавим напоминания — придётся отдельно разрешать автозапуск.
